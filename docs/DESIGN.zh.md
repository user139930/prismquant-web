# PrismQuant 前端設計說明

> 用途：可直接節錄進 ITE4116M 的 Design Specification，或作為 10/29 wireframe review 的講稿。
> 對應企劃書章節：3.2 系統架構、3.5 系統範圍、3.7 非功能需求、2.5 設計原則。

---

## 1. 設計目標

企劃書 2.5 的四條原則直接變成四條前端約束：

| 原則 | 前端落點 |
|---|---|
| Capacity over speed | 不做即時行情跳動、不做秒級輪詢。頁面預設靜態，只有政要監控有 60 秒軟刷新。 |
| Auditable agents | 每個結論旁都有來源與證據鏈；晨報與對話都能展開 `run_id` 與引用事件。 |
| Risk veto | 風控不是一個 tab，而是一條穿過介面的紅線：晨報有閘門摘要、意圖卡有否決標記、風控頁有完整紀錄。 |
| Web first, native later | 單一響應式 Web，390 / 820 / 1180 / 1400 四個斷點；不依賴原生能力。 |

另外三條是我們自己加的：
**數字要能被追問**（所有數值同源計算，不由人手寫）、
**空與錯都要有話說**（loading / empty / error / stale 四態）、
**不假裝**（示例數據一定標示，未接的模組不裝作已接）。

## 2. 信息架構

左側導航按「決策節奏」分三組，而不是按技術分層：

```
今日   ├─ 晨報        ← 一天看一次的地方（A5 產出）
       └─ 代理對話    ← 有疑問才進來（A5 入口）
研究   ├─ 新聞情報    ← A1
       ├─ 政要監控    ← A2
       ├─ 策略與回測  ← A3
       └─ 學院        ← 教育內容，降低訂閱門檻
執行   ├─ 風控閘門    ← A4
       └─ 持倉與績效  ← F-09
```

理由：使用者一天的行為是「看晨報 → 有疑問問 A5 → 偶爾查研究」，
把 A1–A4 放在同一層會讓晨報失去入口地位。

## 3. 視覺語言

沿用組員 `/monitor/` 模組的編輯式風格，避免整合後像兩個產品。

| 項目 | 值 | 理由 |
|---|---|---|
| 主色（墨） | `#1b2430` | 標題、主要按鈕、圖表主線 |
| 強調（紅） | `#c8453a` | 只在三處出現：當前導航、章節紅線、上漲／風險 |
| 上漲／下跌 | 紅 `#c8453a` / 綠 `#1f7a63` | 跟隨內地與香港市場慣例（漲紅跌綠） |
| 背景 | `#f4f5f7`，卡片純白 | 高資訊密度下用色塊分層，不用陰影 |
| 邊框 | 1px `#e6e9ee` | 全站只用髮絲線，圓角 4–8px |
| 標題字 | Segoe UI / Microsoft YaHei 600 | 中文標題不用襯線，避免 SimSun 發虛 |
| 數字 | Georgia，`tabular-nums` | 表格與圖表軸對齊；金融終端的常見做法 |
| 微標籤 | 9px、字距 1.6px、全大寫 | 分區用，不承載資訊 |

### 字級：只有七級

8 / 9 / 9.5 / 10.5 / 11.5 / 12.5 / 13.5 這種「差半級」的字級是介面看起來不整齊的主因——
肉眼分不出差異，只會覺得哪裡怪。所以全站只留七級，任何新元素都必須落在其中一級：

| 級 | 用途 |
|---|---|
| 26 | 指標數字（唯一的大字，Georgia） |
| 22 | 頁面標題 |
| 18 | 次級數字、卡片分數 |
| 15 | 正文、晨報內文、文章內文 |
| 13 | 面板標題、新聞標題 |
| 12 | 表格內容、次要段落 |
| 11 | 說明文字、標籤 |
| 10 | 全大寫微標籤、表頭（字距 1.6px） |

行長也固定：中文正文 `max-width: 40em`（約 33–38 字／行），超過就換行，
不讓文字橫跨整個面板。晨報第一段不用首字放大——它會讓首行只剩幾個字，
反而製造不規則。

不使用的東西：漸層、陰影、發光、卡片堆疊的圓角、圖示字型。
原因：這是研究工具，不是消費 App；裝飾會降低數字的可讀性。

## 4. 頁面結構

### 4.1 晨報（首頁）
自上而下是一條決策鏈，不是儀表板拼貼：

1. **四格指標** — 淨值、今日盈虧、風控狀態、待確認意圖。讓使用者在 3 秒內知道今天有沒有事。
2. **晨報正文** — 三段：市場 → 事件 → 風控。每段都以「哪個代理、幾點、做了什麼」開頭。
3. **四張意圖** — 標的、方向、評分、目標區間、一句依據、四個代理的投票條。被否決的那張永遠顯示原因。
4. **隔夜時間線** — 06:00–08:16 的事件，紅點為利空。
5. **右欄** — 代理狀態、風控閘門摘要、分歧與保留意見。

最後一塊是刻意的：**把「A3 想加倉、A4 否決、A5 裁定」寫出來**，
這正是企劃書說的多代理「可見、可審計」，也是最容易拿分的示範點。

### 4.2 新聞情報
事件簇而非新聞流。每一簇顯示來源數（去重後的證據強度）、情緒、主題、映射標的。
展開後才看到摘要與來源清單。右欄放處理管線與**已知限制**——主動寫出模型弱點，
比被老師問出來好。

### 4.3 政要監控（唯一接真 API 的模組）
三欄：人物 → 發言列表 → 全文。
嚴格遵守 `FRONTEND_INTEGRATION.md`：

- 列表用 `order=published_desc`，游標當不透明字串，切換人物時清空列表並作廢舊請求（用遞增 `reqId` 比對）
- 時間一律本地時區，`null` 顯示「時間未知」，不拿現在時間補
- 正文 `white-space: pre-wrap`，用 textContent 而非 innerHTML
- `archive_only` 與 `verified_page_attribution` 分開標示，措辭不誇大
- 404 / 422 / 503 三種錯誤給不同文案
- 頂部狀態列讀 `/api/v1/system-status`，把「配置開關」與「進程在線」分開講

### 4.4 策略與回測
淨值曲線（策略紅線 vs 基準虛線）、回撤區塊、月度收益條、策略家族表、參數表、收益歸因。
所有指標由同一條序列計算（`statsOf`），所以年化、回撤、Sharpe、波動率不會互相矛盾。

### 4.5 風控閘門
先畫鏈路（A1→A2→A3→**A4**→A5→適配器，A4 標紅），再給六條限額與使用率，
最後是否決紀錄。否決紀錄帶規則名、觸發值、動作與理由——這是 A4 唯一能自證的方式。

### 4.6 代理對話
對話 + 右欄 run 資訊 + 引用來源。A5 的每則回覆下方有可展開的「證據鏈」，
內容是結構化的 `key = value`，不是自然語言——用來示範「不是黑盒」。

### 4.7 持倉與績效
持倉表（含現金）、市場暴露、按代理拆分的收益貢獻。
明確標示「模擬撮合」，並在表下寫清楚匯率折算假設。

### 4.8 學院
一篇主打 + 三張卡 + 右側目錄。內容刻意寫得保守：講因子會失效、講回撤比年化重要、
講我們不做什麼。這比堆賣點更像一個真實的訂閱產品。

## 5. 四種狀態

每一塊有非同步資料的地方都要交代：

| 狀態 | 表現 |
|---|---|
| loading | 面板中央 `⋯` 加一行「载入中…」，不閃骨架屏（資料量小，骨架反而更吵） |
| empty | 幾何符號 + 一句說明 + 下一步（「换一个人物，或清空筛选」） |
| error | 錯誤原文 + 重試按鈕；不把 503 說成「網絡問題」 |
| stale | 保留舊內容，在狀態列標紅；不清空畫面（避免示範時一片空白） |

## 6. 響應式

| 斷點 | 變化 |
|---|---|
| > 1400 | 三欄政要監控、晨報雙欄 |
| 1180–1400 | 政要監控降為兩欄，詳情移到列表下方 |
| 820–1180 | 側欄收窄、晨報單欄、統計改 2×2 |
| < 820 | 側欄變頂部橫向滑動導航、全部單欄、隱藏次要標籤 |

手機不是縮小版：導航改成橫向 chips，狀態列與資訊密度都降一級。
政要監控在手機上依序是「人物 → 列表 → 全文」，用「返回列表」回上一層。

## 7. 三語（簡 / 繁 / 英）

- 簡體與英文是**兩份文案**：`I18N.zh` 與 `I18N.en`，加 `t(key)` 取值，沒有引入 i18n 套件。
- 繁體不另外寫一份：用 OpenCC s2hk 產生的對照表（294 字 + 64 詞）在渲染後即時轉換。
  這樣連資料內容（新聞標題、發言正文、學院文章）也一起轉，
  不會出現「介面繁體、內容簡體」的破綻——這是手寫字典做不到的。
- 轉換用 `MutationObserver` 掛在 `body` 上，只處理新增的文字節點與
  `placeholder / title / aria-label`，所以動態內容（載入更多、聊天回覆、toast）也會轉。
- 詞組表存在的理由：`干` 在「干預」是 `干`、在「乾淨」是 `乾`、在「幹部」是 `幹`，
  單字對照一定會錯；64 條詞組就是為了這類一對多。
- 已知限制：詞組表是從本產品的文案生成，**新增文案若含一對多字**（如「后 / 後」、「发 / 髮」）
  可能轉錯，屆時要重跑一次生成腳本。

## 8. 與組員模組的整合決策

組員給的 `/monitor/` 是原生 HTML/CSS/ES Module，README 建議「整個目錄放進總前端」。
最後沒有用 iframe，也沒有直接搬 `app.js`（它綁死了自己的 DOM），而是：

1. 沿用他的**視覺語言**（色彩、字體、micro label、紅線）
2. 按他的**契約**重寫一份 request 層（同樣的 15 秒超時、同樣的錯誤文案分級、同樣的 `normalizeBase` 驗證）
3. 保留 `/monitor/` 作為獨立入口，兩邊跑同一份資料不衝突

好處是總前端只有一個檔案、一份狀態管理；代價是 `app.js` 之後若加功能，
需要同步一次。這點已寫在整合說明裡。

## 9. 尚未完成 / 下一步

1. **A1 / A3 沒有 HTTP 介面**：Streamlit 與 CLI 都無法被前端直接呼叫。
   最小改動是各自加一個 `/api/v1/...` 唯讀端點，前端把 `D` 換成 `fetch`。
2. **真後端未實跑**：政要監控的資料庫需要 PostgreSQL，本機沒有環境。
   契約層已用 stub 驗過，端到端要等資料庫起來。
3. **圖表互動**：目前沒有 hover tooltip 與縮放。若時間允許，加一條十字準線即可。
4. **登入與權限**：現為純展示。要真的接，需要後端先有 session 或 token。
5. **無障礙**：已加 `aria-label`、focus ring，但 `prefers-reduced-motion` 未處理；表格尚缺 `scope`。
6. **PWA 只做了最小可用**：有 manifest 與 service worker（network-first），
   可安裝、可離線開殼，但沒有背景同步與推播。
